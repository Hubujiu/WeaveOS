# Personal named table presets

Source: approved [PRD](https://app.notion.com/p/3ed2f5a9e6488156bf31f129d467c340), accepted [ADR008 A1–A7](https://app.notion.com/p/3ed2f5a9e64881639ba2c434fb6c7c34), read back 2026-10-02. ADR007 query semantics remain authoritative.

`/api/v1/personnel/table-presets`: GET requires exactly `view=members|events`, returns complete items ordered updatedAt DESC/id ASC. POST creates (201/Location); item GET reads the Session-owned resource, PUT replaces content with positive safe-integer version CAS, and DELETE requires exactly `?version=N` (204). Owner/view/slot/id cannot be updated. Other owners receive the same 404 as missing resources; each access checks live personnel.manage and Session, mutations use existing CSRF/Origin. DTOs are closed, recursively reject duplicate fields and malformed Unicode, and retain the existing envelope.

Name is trimmed at its edges, counts 1–100 Unicode characters and preserves exact case. Name uniqueness and slots are scoped to owner/view. A unique slot 1–20 imposes the hard quota under concurrency; allocation uses the existing draft RC retry pattern. Name, quota and version conflicts have distinct registered codes. No eviction, expiry, active state, queryVersion, row results, business revision bumps or audit writes.

Independent byte caps: filter canonical UTF-8 JSON 16384; canonical content `{view,name,filter,hiddenColumnIds,schemaVersion}` 32768; complete received body 65536. Omitted/null filter means visibility-only. A stored filter is one AND leaf group or OR of AND leaf groups, validated by the existing compiler (20 global leaves/3 group levels/typed NULL, relations and times). Unsupported shapes are rejected instead of transformed. Display column IDs differ from relation filter field IDs. At least one configured business column remains visible; auxiliary columns never enter the whitelist. Hidden IDs never enter query DTOs or alter backend fingerprints/security.

Migration 00005 preserves canonical filter text independently of jsonb formatting. Names use exact C collation; slot/name unique constraints, FK, schema/version/bytes checks and owner/view/update index are explicit. Application UPDATE grants cover only content/version/updated_at. The reviewed fixed role hash and exact compatible migration hash are registered; no broad migration trust or production role installation.

The overall 32768-byte cap is checked separately, but it is unreachable by otherwise legal current DTOs: filter is at most 16384 bytes, the name is at most 100 characters (at most 600 JSON bytes including required escapes), and hidden IDs come from a short fixed array. Tests directly reach 16384/16385 filter and 65536/65537 transport boundaries. A 32768/32769 example would already violate another frozen constraint, so it cannot prove an independent whole-content boundary. This limitation is reported for root review; capacities are not expanded for testability.
