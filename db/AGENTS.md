# 数据与迁移

先读根 AGENTS、Database 入口，再读本版本设计、ER、DDL，以及涉及的对象/字段记录；会话变更加 Redis 规范与 ADR-001。只读数据库 schema 或首页不等于读取记录。

设计待评审就不得直接转成生产 migration。先从已确认约束写真实 PostgreSQL/Redis 的失败集成测试，再编写迁移/SQL/存储行为。并发、事务、唯一键、过期和撤销不能仅靠 mock 验收。

migrations 为部署结构的可执行依据；字典描述设计/字段含义，两边必须一致。发布过的迁移不改写，后续修改使用新迁移；不使用启动 AutoMigrate 偷改结构。未批准迁移工具前不安装候选工具或生成伪迁移。

字段名与类型、主键、唯一约束、外键、索引、CHECK、默认值和变更/回退策略均应明确。数据库用 snake_case，不将数据行当 API DTO。不新增超出本期范围的角色、部门、租户、文档或第三方身份表。

测试只使用隔离数据，禁止真实用户数据/凭据/备份入库。当前没有可执行 migration，所有表仍是待评审设计。
