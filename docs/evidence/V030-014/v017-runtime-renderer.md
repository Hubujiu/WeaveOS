V014 owns only the forms renderer/selector/types/guard boundary. No runtime record transport, owner definition read, or record CRUD is added here.

## Imports and contracts

`apps/web/src/applications/forms/index.ts` exports `FieldRenderer`, `DisplayField`, `FieldValue`, `ReferenceDisplay`, `ReferenceCandidate`, `ReferenceCandidatePage`, `LoadReferenceCandidates`, and `LeaveScope`.

- `DisplayField` requires only `id`, `name`, `kind`, `required`, and `presentation.helpText`; optional runtime `input` exposes `options`, `decimal`, `timePrecision`, `referenceKind`. The legacy owner `config` is read only inside the renderer. A V017 RuntimeField with these projected properties is assignable directly, as the typechecked harness shows. The renderer does not read owner `default`, DDL, dependencies, or permissions.
- `FieldRenderer` remains controlled: V017 supplies `value` and `onChange` (when editable), and sets `readOnly` from effective row and field capability. Omission, explicit null, empty string, and false remain decisions of the V017 caller; this component does not invent defaults. Boolean input keeps the source checkbox, adds a visible `未设置`/`是`/`否` state and an explicit `清空` action; null never becomes false without an interaction. Required fields may temporarily be cleared in the draft, with save validation left to the service.
- For member/department, pass `referenceDisplay` from `Record.referenceDisplays[field.id][selectedId]` when available. `{id,label,deleted:true}` remains visible as a tombstone and is never offered as an active candidate. A readable ID without a current display shows “引用信息不可用（需修复）” rather than an empty or fabricated label. Readonly fields do not enumerate and never reuse an earlier local candidate label. The renderer no longer caches a selected label. Its `onChange(value, selectedCandidate?)` passes the candidate returned by the ordinary candidate endpoint as optional interaction data; V017 may hold that label in its own unsaved draft display state and must clear/revalidate it on authoritative refresh or permission change.
- Editable reference fields pass `loadReferenceCandidates(request, signal)` where `request={q,pageSize:20,pageToken}` and the result is `{items,nextPageToken}`. Only active items can be selected. The picker trims searches to 100 Unicode code points, resets pagination on search, aborts obsolete requests, reports loading/error, and displays a real “加载更多” action. V017's transport closure must call the ordinary field scoped `/reference-candidates` route with its own app/view/field/action/record context and map the service envelope `data.items` + `meta.pagination` to this page shape. Do not call V013 owner-only member/department candidate routes for ordinary record use. Server save remains the authority for eligibility.
- Pass `referenceScopeKey` as the complete actor/app/view/(recordId, draftId or clientDraftId)/field identity, serialized stably. A change remounts the selector, clearing query, candidate pages and active requests. V017 owns construction of this key and must use a distinct UUID `clientDraftId` for a new unsaved record rather than pretend that it has a server `recordId`.
- `LeaveScope` has discriminated `structure` (`actorId`,`appId`), `designer` (+`viewId`), `record` (+either `recordId` or `clientDraftId`), and `draft` (+`draftId`) variants. The existing `LeaveController` handshake and registration-bound unsubscribe behavior are unchanged. The registry harness key distinguishes stored record IDs and local client draft IDs, so two resources in one view do not overwrite each other.

V017 must keep each new unsaved record's `clientDraftId` stable for that editor instance in the current SPA. It is a local scope identity and is not submitted as a server record ID.
