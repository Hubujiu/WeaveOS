## 1. 产品与统一组件

服务端在完整结果上筛选、排序后按 `page/pageSize` 分页，支持任意页跳转；不保存历史结果快照。不相关当前查询的变化不要求刷新；相关变化中止当前操作并提示必须刷新重查。显式刷新回第 1 页，保留条件、排序、页大小、列宽和列顺序，清空行选择。

仅真实数字和时间业务列可升降序。当前成员表没有这种业务列，不提供文字排序；记录表只有时间列排序。默认稳定顺序继续为成员 `created_at ASC,id ASC`、记录 `occurred_at DESC,id DESC`；用户时间排序使用唯一 ID 兜底。不把枚举/布尔伪装为数值排名，不把序号当业务排序字段。

自定义筛选是排除不符合记录，和排序是两项独立功能。搜索同一行放漏斗入口，不另建排序面板；正常列头排序用排序图标。支持 AND/OR 嵌套组。

直接统一现有 Arca `Table` / `TableColumn` 的受控 API，移除 `PersonnelTable` 和 `PersonnelColumn` 参数转换，不创建第二适配器。业务只声明列、筛选和行操作；公共 query state 管请求、迟到响应、过期和查询状态提交。公开页码从 1 开始。保留原版拖列、列宽、选择、虚拟滚动、固定表头、空行填充、完整分页、键盘、焦点和动效。加载期间不因卸载丢失列状态。身份/模板卡片保持视觉，只接必要一致性联动和草稿。

记录安全 display 值由后端统一生成，不依赖当前成员页；查询投影使用集合读取，防止全结果 N+1。保持安全字段允许清单，不对原始 JSON 文本排序，不扩大 `auth.authentication_events` 读取权限。

## 2. 筛选与查询协议

`FilterGroup { operator: "and" | "or", children: (group | condition)[] }`；`condition { field, operator, value }`。根无条件时不提交 filter，空组非法。根组计第 1 层，最多 3 层组、20 个叶条件、规范 UTF-8 JSON 最多 16384 字节；全树统一计数，不转为 DNF。现有 search 和快捷筛选与树整体 AND。

- 文本 `eq/neq` 精确、大小写敏感，不提供大小比较。
- 数值 `eq/neq/gt/gte/lt/lte`，拒 NaN/Infinity；本期不为了排序新增虚构数值业务列。
- 枚举、布尔 `eq/neq`。
- 多值身份/部门 `eq` 表示 EXISTS 该 ID，`neq` 表示 NOT EXISTS 该 ID；空集合满足 `neq`。`身份!=A AND 身份!=B` 不包含 A 或 B；不能用 EXISTS(不同 ID) 替代否定。
- 单值普通比较不匹配 NULL。`value:null` 仅允许 `eq/neq`，分别为 IS NULL / IS NOT NULL；不得把普通 `neq` 写成 NULL 也匹配。
- 时间显示时区、规范成绝对边界；最近 7 天在本轮查询固定，刷新重算。日期 eq 按该时区当天半开区间，不能默认 24 小时；时刻精度须明确。所有日期/时区/运算符均由服务端验证。
- GET 现有列表使用 `filter` JSON query 参数。字段、类型、长度、层数和重复/未知参数统一验证，非法 400；不提供任意 SQL。

保持现有 envelope `code/message/data/meta` 和 `data.items/total/page/pageSize`，新增 `queryVersion/sort`，记录另返回已生效 `range`。`queryVersion` 是不透明上下文 ID，不是排序游标、权限或可跳过检查的凭证。

错误：相关差异为 `409 COMMON_QUERY_CHANGED`；上下文缺失/空闲到期/LRU 淘汰为 `409 COMMON_QUERY_CONTEXT_EXPIRED`，不误报数据变化。校验重试耗尽沿用 `503 COMMON_SERVICE_UNAVAILABLE` 并明确可区分的 busy 原因，不复用旧码表示另一 HTTP 状态。对象并发继续 `PERSONNEL_CONFLICT`；草稿冲突/容量按 OpenAPI 的明确登记。缺失新必填输入为 400，旧浏览器需刷新；不能静默关闭一致性保护。

## 3. 当前完整结果差异检测

`people/configuration/activity` 三个 revision 仅作无变化快路径与写入复验。依赖范围：成员 people+configuration；记录 people+configuration+activity。未来模块独立定义自身依赖，不共享人员三个标记。

指纹覆盖完整匹配 ID 集合、实际排序值、安全显示字段及必要关联值，包含已选筛选对象的相关存在性/名称；不只是当前页。不把对象 version、未用选项、无关说明或计数混进显示摘要。SHA-256 流式计算，规范编码明确类型/NULL/长度和数组顺序，不朴素拼字符串。指纹只判当前结果与基线是否不同；A→B→A 或新增后删除恢复原结果允许继续。摘要存在概率碰撞边界，不冒充数学无损比较。

旧查询校验、新条件 baseline、total、page、返回 revision 必须来自同一短 `REPEATABLE READ` 事务。revision 未变可复用指纹结论；变化则完整重算，相同允许操作并推进已验证 revision，不同才拒绝。改条件/排序先验证旧查询，再计算新查询，不能拿新条件和旧指纹比较。

现有 Redis 保存有限查询元数据：session 归属、视图、规范条件、固定时间范围、total、指纹、已验证 revision、协议版本；无业务行或匹配 ID 列表。opaque queryVersion 绑定当前 session，权限仍实时检查。新条件创建新 context，旧条件不原地改；同 baseline revision 推进用 CAS 防迟到覆盖。空闲 30 分钟 TTL，每 session 最多 20 context、LRU 淘汰。不能把 query TTL 用于草稿，也不能把已成功业务写和 Redis 元数据更新伪装成分布式事务。

## 4. 写入、锁与所有失效路径

完整哈希在锁外：先用短 RR 校验当前指纹并记 revision r；随后 RC 写事务按固定顺序 people→configuration→activity 获取必要 revision 锁，再重新鉴权、保留原 auth_version/账号和实际授权对象锁、核 r、核对象 version、执行领域写和审计，revision 同事务更新并提交。

r 又变化须结束尚未执行领域修改的事务，重新锁外精确预校验；最多两次额外预校验，遵守整体截止时间。仍不稳定返回明确繁忙，不能直接说查询已变化（可能是不相关修改），不重放已执行或结果不明的写。普通读取不取公共写锁。

三个 revision 是人员数据集合级有限写闸门，此取舍须补入 ADR006；不是所有应用请求共用全局排他锁。锁内无全结果 O(M) 扫描，但原鉴权和实际写操作仍有自身成本。

必须覆盖：注册/Bootstrap 的真实新账号，账号可见字段/状态变化；成员身份/分组配置；部门、身份、模板、权限目录及关系变化；人员和邀请码事件新增；热库归档/过期删除。冷库独立删除不影响热查询。幂等无变化不递增；AuthorizeWrite 初建 member_configuration(version=0) 不算显示变化。只改密码/auth_version 和普通登录退出事件不算表格数据变化，安全检查仍生效。

表结构在 00003 新迁移冻结；实际失效触发器/锁函数应在后续新迁移和真实并发 RED 后由契约/整合责任者完成。不得仅有 revision 表就声称全部写路径已覆盖，不改已发布 00001/00002。

## 5. 账号持久草稿

PostgreSQL 按账号持久、显式保存，无自动过期。每账号最多 20 份，每份 payload 规范 UTF-8 JSON 最多 65536 字节；超限报错，不静默删除。刷新/关闭浏览器/Session 结束不删除；本人重新登录且仍有权限方可恢复。

范围：成员身份/分组、部门新建/改名、身份及权限模板新建/编辑；不保存密码、邀请码明文、Session 或完整结果。保存输入、targetId、原 baseVersion、draftVersion；不是历史结果快照。保存不改正式业务、不增三个 revision、不产生正式配置变更事件。

撤权不能读写。恢复读取最新对象/关系显示差异并保留原 baseVersion；用户明确解决后才提交。目标删除/引用无效不自动重建或丢弃输入。独立 draftVersion 防多标签覆盖；业务成功只清理实际提交的那版草稿，优先同事务，较新草稿必须保留。删除草稿也须版本检查。草稿所有者从 Session 取得，不能信客户端 ownerId。

## 7. 时间空间与性能验收

N=总表行数，M=匹配数，K=页大小，D=期间变更条数，Q=活跃查询数，F=关联传播量，B=每行投影字节，L=规范条件大小，offset=(page−1)K。

首次成本 Cq(N)+Jq(M)+Sq(M)+O(MB)；Cq 包含筛选/关系访问，Jq 包含关联和派生显示，Sq 无索引时可达 O(M log M)，数据库排序可落盘。应用流式存储约 O(KB+B+L)，不能把数据库内存也说成常数。无 revision 变化仅检测 O(1)，offset/筛选/取页/关联不是 O(1)，深页可能扫描前缀；可复用已证明仍有效的 total。revision 变化即使最终无关，也可能付全量复核成本；改条件最坏旧新两次计算。Redis metadata O(QL)，草稿有界；不先建日志平台/缓存依赖图。

日志路线需计 D×Q、关联 F、旧值/旧关系和留存缺口，D=1 也可能 F≈N。当前批准比较现结果，不承诺期间从未变化。超时/资源不足不能降级为抽样、当前页、总数比较或截断；明确失败、不执行依赖该校验的写。

测试覆盖不同 N/M/K、浅深页、无变/无关/相关变化、高扇出、复杂记录摘要、并发预校验失效。记录执行计划、扫描量、排序落盘、内存、耗时、写锁持有时间；具体性能阈值由根依据测量验收，不虚构压测通过。
