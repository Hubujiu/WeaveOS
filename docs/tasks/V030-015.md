Core modules in this branch: `appaccess` evaluates complete trusted grant
tuples, `appquery` compiles typed exact filters, permission-conditioned
row/field SQL and safe arbitrary pages, and streams a complete projection
digest; `appdrafts` implements owner-bound partial PATCH/consume/
discard/cursor list in caller-owned PG transactions, and `apprecords` writes
typed physical rows with table-gate/authorization/fence/audit ports and CAS.
These are **partial integration cores**: the fixed V015 base does not contain
V030-013's later field normalizer, form registry or typed migrations, and no
shared branch yet supplies live data grants, record/draft operation kinds,
query-context reuse, source hooks or HTTP composition. Core PG fixtures are
synthetic and run as DB owner, not a
runtime-role/full API certification.

during this execution (read only, 2026-10-03). It now supplies hot7 typed

The isolated PG scale probe ran 10k/100k/1m typed rows and sequential
C=1/20/200 core rehashes. Broad one-million-row C=200 exceeded the unchanged
10-minute test deadline twice; C=20 took 45.3 seconds. The 10% and 0.1%
million-row C=200 variants completed in 63.6 seconds and 0.531 seconds.
These samples exclude live Q36/Session/policy/registry/API costs and are not
the required full-chain capacity gate. The lead must review the broad cost;
no new algorithm or raised product timeout was silently substituted.
The compact experiment measured 200 identical million-row criteria at one
cache miss/0.956 seconds and 200 distinct criteria at 200 misses/4m02s; it
also demonstrated a false negative if a writer mutates values without a
recordVersion bump. This candidate cannot be adopted until all record,
schema and source writers satisfy the proof and full-chain matrix. A separate
literal ASCII-folded quick-search PG probe scanned 1m text rows in about
5 seconds despite a text BTree; no specialized index was selected.
