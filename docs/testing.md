# 测试先行与独立验收

## 必须遵守的顺序

先把独立需求转为可执行验收用例，然后写测试并观察 RED，之后才能编写被测行为；最后 GREEN、重构、回归。所有可执行代码（含工具、配置行为和数据库迁移）适用。禁止先实现再“覆盖”测试。

每个用例至少包含：需求来源/章节或 ID、Given 输入和前提、When 行为、Then 可观察结果及边界。预期值从需求、数学/协议定义、独立审查的样例获得，不能用实现函数、生成的当前响应或复制实现的另一份算法计算预期。

阅读现有实现用于定位缺陷、了解接口和依赖可以；它不是行为正确性的裁判。纯 characterization 描述的是“目前怎样”，须单独标注，不能证明满足需求。

## RED 的有效证据

记录实现前的测试文件版本、提交/不可变快照、执行命令、环境、退出码、失败用例及断言失败原因。测试运行器已成功加载并到达目标断言；不存在接口时可添加最小声明/占位，但不得提前实现行为。导入失败、网络超时、数据库未启动或语法错误不是目标 RED。

RED 测试先保存，GREEN 不改正确的验收断言。测试设计确有错误时回到独立来源核实，记录理由后修正测试并重新 RED，不能以“现在实现就是这样”为理由改断言。禁止伪造日志、提交时间、失败截图或已读来源。

## 分层与边界

单元测试关注领域规则，不断言无关私有方法或偶然调用顺序。只 mock 外部边界，不 mock 被测用例本身。时间用可控制时钟，随机性用可注入来源；不要靠长时间 sleep 证明 Session TTL。

HTTP/契约测试从 OpenAPI 和 ADR-002 导出行为样例，校验状态码、Envelope 及协议例外、认证与错误语义；生成的类型不能代替对实现的验证。RPC 有实际跨服务边界后才增加 Proto 兼容、状态详情与跨语言测试。

PostgreSQL / Redis 集成测试使用真实、隔离的测试实例：事务原子性、唯一性、邀请码并发消费、TTL、续期、退出与撤销竞态不能只用内存假对象验收。迁移检查空库、升级路径、约束/索引和评审要求的回滚/恢复策略，禁止对生产数据库跑测试。

前端组件/浏览器测试按 PRD 和原型验证用户可见结果、键盘操作、错误与 Loading；测试不能只是把当前 DOM 或截图保存为“正确答案”。未审核的快照更新不允许自动接受。UI 是否符合批准组件与原型还需要人工/视觉审查。

## v0.1.0 首批业务用例方向（尚未实现）

从 PRD / ADR 重新确认后再落地：无/无效/已用邀请码拒绝；注册失败不消费邀请码；并发同码最多一个成功；注册成功不自动登录；正确/错误凭据与账号状态；1 小时空闲过期与成功认证活动滑动续期；退出后不可复用；普通用户不可使用 Bootstrap 特例；密码/凭据不泄露；Redis 故障不放行。具体字段、状态码、Cookie 属性和事务策略必须来自已确认契约，不在此臆造。

## 不允许的“变绿”方式

删除断言、放宽正确预期、跳过失败用例、仅测试自己的 mock、用被测实现算 expected、复制算法自证、降低覆盖门槛、自动接受 snapshot、凭覆盖率替代验收。Bug 修复必须先有能够重现缺陷的失败测试；重构应保留既有行为测试，新增行为另走 RED。

纯文本/格式改动可标 `TDD: N/A`，但必须说明不影响可执行行为并做相应文档校验。运行环境不足时写 `NOT RUN` 或 `BLOCKED`，不能写 PASS。
