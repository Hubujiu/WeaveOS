# Go Web BFF

先读根 AGENTS、Notion 路由、测试规范；认证改动必须实际读取当前 PRD 与 ADR-001，HTTP 改动加 ADR-002，选库/边界加 ADR-003，持久化加已评审数据资料。

先写需求驱动测试并实际 RED，再实现用例。按已接受方案分离 HTTP 适配、认证/邀请码应用行为和存储边界；认证模块可访问自己拥有的数据，不跨领域访问他库，不在 Handler 堆 SQL。具体目录和依赖等出现真实需求且评审就绪再引入，不生成空壳服务。

只有 BFF 认证边界处理密码，业务模块只消费身份上下文。使用服务端 Redis Session 与受保护 Cookie，不切换为纯 JWT。无法验证会话时不放行，外部传来的内部身份头不可信。

邀请码消费和用户创建的原子性、同码并发、重置/禁用/退出与续期竞态必须以真实存储集成测试验收；内存 mock 不能证明事务/TTL 正确。时钟与随机性应可测试，不靠 sleep 等一小时。

先从需求确认重置/撤销语义，不硬编码未经评审的账号模型、密码参数、端点或错误码。Bootstrap Admin 特例不能演化成隐藏的通用权限系统；不在日志暴露凭据。

当前没有 go.mod、Go 服务或业务测试；不得声称 `go test ./...` 已通过。
